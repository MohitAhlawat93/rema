# Cloudflare migration: non-production preparation

Current stage: code prepared on a feature branch. The Vercel site remains the live site.

## What moves
- Static HTML/CSS/JS stays generated by `npm run build` into `dist`.
- Pages Functions in `functions/` route existing /api endpoints using a Fetch/Node adapter.
- The Pages middleware handles published SEO HTML, sitemap and images sitemap.
- `public/_routes.json` excludes static assets from Functions billing.
- Existing Supabase data is **not** copied by this change.

## Mandatory deployment gates
1. Owner approves actual published content and hosting acceptable-use terms.
2. Create a client-owned Cloudflare account with independent login, recovery and billing.
3. Create an isolated client-owned Supabase project; migrate only client information and media. Test RLS and restore.
4. Set environment secrets securely in Cloudflare: SUPABASE_URL, SUPABASE_PUBLISHABLE_KEY,
   WITNESS_LEMA_INTERNAL_SECRET, SIGNATURE_ADMIN_LOGIN_ID, SIGNATURE_ADMIN_PASSWORD_HASH,
   SIGNATURE_SESSION_SECRET, RAG_TENANT_ID and RAG_TENANT_SECRET; GROQ_API_KEY optional.
   Never put secret values in Git, web pages or a shareable checklist.
5. Create Pages project using build command `npm run build`, output `dist`, Node 22+.
   Use `nodejs_compat` at compatibility date 2026-10-12 or later.
6. Set verified SEO_SITE_ORIGIN and SEO_INDEXING_ENABLED=true only after domain/DNS ownership
   and content approval. Make preview environments noindex.
7. Test admin login, draft/publish, content, reviews, chatbot, RAG, real SEO HTML,
   sitemap, mobile layout, permissions and domain security. Revoke all old keys after cutover.

## Limitations
- Moving Vercel's functions involves real runtime compatibility tests, not just a static build.
- R2 upload/download logic is deployed, and the staging `MEDIA_BUCKET` R2 binding is configured. Authenticated upload, delete and publish have not yet been verified. Workers AI fallback is implemented but not yet end-to-end tested.
- Configure the client-owned R2 bucket binding as `MEDIA_BUCKET` and Workers AI as `AI` only after authorization; add `COOKIE_SECURE=true` for production HTTPS.
- The admin's existing photo button uploads optimized JPEGs through R2 once bound. Validate the Supabase Edge Function changes on a **new client-owned database** before turning on this flow; otherwise published R2 paths may be rejected.
- Do not delete media directly from storage when merely removing a photo from a draft. Schedule safe garbage collection after checking published references.
- Full source code remains with the developer according to the software licence;
  owners get content/export/website operation rights.
- Free services have traffic/usage limits. Supabase Free may pause inactive projects.

## One-time automated staging deployment authorization

The Pages project is **Direct Upload**, not Git-connected. This is intentional:
clients do not need GitHub or source-code access.

1. In the *developer's* Cloudflare account, create a restricted API token
   with **Account > Cloudflare Pages > Edit** for the selected staging account.
   Use a short expiration for testing. Do not place it in source or chat.
2. Open the developer's GitHub repository > Settings > Secrets and variables >
   Actions > New repository secret. Name it exactly `CF_STAGING_API_TOKEN`.
   Paste the token there. Never place it in a public repository variable.
3. Run `Cloudflare staging — deploy reviewed branch` from Actions after
   the workflow reaches the default branch; **while it exists only in a feature
   branch**, a push changing the workflow file triggers the staging run.
4. GitHub builds/tests and uploads `dist` plus Pages Functions via Wrangler.
   It uploads *feature-branch source* to the **main deployment branch of the
   independent staging Pages project**; it does not merge the GitHub branch or
   deploy to Vercel.
5. The workflow runs `scripts/cloudflare-staging-smoke.mjs` against
   `https://lema-website-staging.pages.dev`. All publicly exposed test pages
   must remain noindex. Credentials must never print into Actions logs.
6. Revoke the temporary Cloudflare token when finished testing.
